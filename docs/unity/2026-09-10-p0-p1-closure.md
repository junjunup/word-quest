## 本轮合同

- 目标：完成 Unity 普通学习的输入与反馈闭环、可追溯且可重试的学习记录、可信报告，以及可恢复的今日学习。
- 范围：Unity Domain / Application / Gameplay / Infrastructure / UI、配套 Express 模型与接口、必要测试和 CI、交接文档。
- 非目标：P2、画面素材重做、商业化功能、改变 Boss 战斗规则、重写所有旧学习模式。
- 禁止操作：覆盖已有 Sprout 素材导入修改、修改旧网页客户端、对真实数据库迁移或回填、提交/合并/推送/部署、付费生成。
- 验收：输入与取消边界有自动化证据；重复记录不重复结算；纠正不增加独立掌握收益；首答与反馈完成后才推进今日队列；真实 Unity HTTP + 隔离 MongoDB 联调；桌面构建与启动检查。
- 停止点：代码、自动验证、文档和本地构建交付。上线需服务端与 Unity 同步发布；本轮不发布。

### 模块与数据流

- `LearningAttempt` 构造明确的证据字段；`PendingSyncQueue` 将答题队列与关卡结算队列分开，均按用户隔离。
- `GameFlowController` 管理题目请求、首答、纠正、反馈确认和世界恢复；`DailyLearningPlan` 保持固定队列分母。
- `DailyLearningService` 对接新的今日学习与证据接口；Home、今日预览/完成面板和 Report 消费同一服务器事实。
- `learningAttemptService` 校验词条、词书和会话归属，以服务端判题为准。唯一索引覆盖同用户 attemptId、同遭遇/阶段、今日同词首答；同 ID 改变答案返回 409。
- `masteryService` 用每词版本条件更新与已应用记录表，保证一个事实只产生一次掌握度副作用。记录投影或日志保存前崩溃，可以由同 ID 重试补全。
- 采用单文档原子更新以兼容当前单机 MongoDB，不强制引入副本集事务。已应用记录表随学习增长，后续大规模运营需监测单词文档大小并规划归档。

### 新增接口

所有接口均位于 `/api/learning` 并要求认证：

- `POST /quiz-record`：携带 `attemptId`/`attemptPhase` 的请求进入新协议；旧请求继续兼容。
- `GET /evidence?wordbookId=...`：分层学习证据与复习状态。
- `POST /daily-sessions`：创建或恢复固定队列。
- `GET /daily-sessions?wordbookId=...`：只读检查该词书未完成会话。
- `GET /daily-sessions/:id`：队列、已完成词、待确认反馈、完成摘要。
- `POST /daily-sessions/:id/feedback`，`{ wordId }`：首答存在后幂等确认反馈。
- `POST /daily-sessions/:id/end`：明确结束当前轮，保留学习事实。

新增字段均向后兼容；旧记录不回填为无提示答题。旧独立复习、发音、挑战等协议没有提供完整辅助信息的记录继续归 unknown，不能据此声称独立回忆。新的今日学习、普通冒险与 Boss 答题使用新证据协议。

新客户端依赖本轮配套服务端。发布时应先发布兼容服务端、确认新增索引建成，再发布 Unity。回滚客户端可保留新增字段和数据；不应删除学习事实或索引来做回滚。本轮只在临时数据库建索引，没有操作真实数据库。
