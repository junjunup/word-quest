# Unity 客户端 P1 首次学习闭环优化设计

## 背景

P0 已经解决冷启动空白、认证异常、密码遮罩和键盘焦点问题，但登录后的产品体验仍然像“功能目录”：

1. 首页平铺八个同权功能，核心学习入口只占其中一格。
2. 今日进度只有数字，没有告诉用户下一步学什么。
3. 关卡页能显示锁定与星级，但没有推荐路径或总体进度。
4. 结算页把“再次挑战”固定为主操作，通关后无法自然进入下一关。
5. K12 用户需要更短、更明确的决策路径，而不是先理解整套系统。

用户已经授权持续自主优化并要求不再逐项询问。本阶段把“登录后完成一次学习并继续下一步”做成完整纵向切片，不同时改造课程内容与服务端。

## 本阶段目标

完成后，用户应能沿着清晰的单一主路径前进：

`首页推荐任务 → 推荐关卡 → 游戏 → 结算反馈 → 下一关或重试`

具体目标：

- 首页首屏只有一个视觉最强的学习主行动，直接进入推荐关卡。
- 今日目标、推荐关卡、预计单词量与累计进度在主行动周围形成连续语义。
- 复习和每日挑战保留为次级学习行动；报告、词库、社交、AI 与资料保留为工具入口。
- 选关页明确显示完成数、推荐关卡、锁定原因和星级，不只依赖颜色表达状态。
- 通关且进度已保存或待同步时，结算页优先进入下一关；失败或进度被永久拒绝时优先重试。
- 首页、选关和结算共用同一套推荐规则，避免三个屏幕各自判断。
- 现有 180 关、难度、词书和全部功能入口不丢失。

## 方案比较

### 方案 A：只重排 UXML 和文案

把“开始冒险”按钮放大并缩小其他卡片。改动快，但推荐关卡仍然未知，选关和结算没有连续性，核心问题只被视觉遮盖。

### 方案 B：本地学习旅程规划器驱动三个关键屏幕（采用）

新增纯 C# `LearningJourneyPlanner`，根据本地关卡目录和服务端关卡状态计算推荐关卡、完成数与下一关。首页、选关、结算只负责展示和触发动作。

这个方案不改变 API，又能以 EditMode 测试覆盖边界；以后接入 K12 课程图谱时，只需替换规划器输入，不必重写三个屏幕。

### 方案 C：新增完整课程任务与推荐服务

服务端维护年级、课程标准、知识点图谱、每日任务与自适应推荐。它是 K12 的长期方向，但当前缺少课程内容和教学策略数据，直接实施会把 UI 优化扩张为一次新的平台迁移。

## 学习旅程规则

`LearningJourneyPlanner` 接收 `ContentCatalog` 与可选的 `LevelsStatusDto`：

1. 有服务端状态时，按目录顺序选择第一个“已解锁且未完成”的关卡。
2. 如果所有已解锁关卡都完成，选择最后一个已解锁关卡用于巩固。
3. 服务端状态缺失或格式不完整时，安全回退到目录第一关。
4. 完成数只统计服务端明确标记为 `completed` 的关卡。
5. 下一关按本地目录顺序计算，不假设每章固定 30 关。
6. 只有本次通关且进度已保存或进入当前账号待同步队列时，结算页才允许“进入下一关”。
7. 最后一关完成后，主行动回到关卡地图，不制造不存在的下一关。

规划器只产生结构化数据，不产生 UI 文案，也不执行导航。

## 首页信息架构

首页拆为三层：

1. **今日主任务**：欢迎语、今日完成量、推荐关卡、单词量、预计时长和“继续学习”按钮。
2. **关键学习行动**：今日复习、每日挑战、每日奖励。
3. **更多工具**：无尽模式、报告、词库、社交、AI 导师和个人资料。

主页先同步渲染本地第一关作为安全占位，再异步加载关卡状态并更新推荐任务。网络失败时主任务仍可进入第一关，其他功能不被阻塞。

## 选关页

顶部增加学习路径摘要，包括：

- `已完成 X / 180 关`
- `推荐：第 C 章 · 第 L 关`

关卡按钮使用文字明确状态：

- 推荐关：追加“推荐”
- 锁定关：追加“完成前一关后解锁”
- 已完成关：保留星级并追加“已完成”

推荐关增加金色描边，但文字标识确保高对比或色觉差异场景仍可理解。

## 结算页

结算卡片先回答三个问题：

1. 结果如何：通关、星级、分数、正确率、连击。
2. 学到了什么：正确题数、错题数和一句基于结果的简短建议。
3. 下一步是什么：
   - 通关且可推进：主按钮“进入下一关”。
   - 未通关或进度被拒绝：主按钮“再试一次”。
   - 最后一关完成：主按钮“返回关卡地图”。

报告和主页仍保留为次级动作；当下一关可用时，“再次挑战”保留为次级动作。

## 视觉与可访问性

- 沿用森林绿、羊皮纸和金色，不引入渐变、紫色或新品牌语言。
- 使用现有 4/8 像素节奏，减少首页等权大卡片。
- 主按钮至少 48 逻辑像素高，关卡按钮保持键盘可聚焦。
- 状态同时使用文字与样式，不只依赖颜色。
- 1280×720 下主行动无需滚动；窄窗口允许自然换行和滚动，不发生水平裁切。
- 不加入无法稳定显示的 emoji 图标；使用中文短标签保证字体覆盖。

## 状态与错误处理

- 关卡状态加载中：首页显示第一关的安全任务，选关页显示本地目录。
- 关卡状态加载失败：不显示虚假的完成数；摘要提示“学习进度暂不可用”。
- 每日统计加载失败：今日进度保持 `0 / 20`，主行动仍可用。
- 下一关启动失败：沿用现有 `StartLevel` 恢复到关卡页的行为。
- 离线待同步的成功通关允许继续下一关，并在结算状态中明确告知已加入待同步队列。

## 测试策略

1. EditMode：规划器选择第一个已解锁未完成关卡、全完成巩固关、缺失状态回退和跨章节下一关。
2. EditMode：首页主行动调用推荐关卡，全部功能入口仍可达。
3. EditMode：选关页为推荐、完成、锁定状态输出可读文本并正确禁用。
4. EditMode：结算页在可推进、失败、永久拒绝和最终关卡场景选择正确主动作。
5. PlayMode：主页面 UXML 与样式加载，1280×720 下关键控件存在且可聚焦。
6. 全量运行静态验证、EditMode、PlayMode、Windows/macOS 构建验证，并保存 macOS 可见界面证据。

## 非目标

- 本阶段不把 CET-4 词库替换为 K12 分级课程。
- 本阶段不新增服务端推荐 API、知识图谱或家长/教师端。
- 本阶段不重做游戏世界、美术资源和答题机制。
- 本阶段不删除或隐藏任何已迁移功能。
