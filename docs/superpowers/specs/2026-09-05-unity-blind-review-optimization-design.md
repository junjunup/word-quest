# Unity 盲审关键路径优化设计

日期：2026-09-05

基线分支：`feat/unity-client-migration`

实施分支：`codex/unity-blind-review-optimization`

目标版本：Unity `6000.5.3f1`

## 1. 背景与目标

本轮面向毕业设计评委的首次体验。评委应在第一次打开客户端后的 5–10 分钟内理解三个核心事实：

1. Word Quest 是一套可运行的英语学习系统，而不只是展示页面。
2. 游戏探索、词汇答题、学习反馈和后续复习形成完整闭环。
3. Unity 客户端具备稳定、清晰、可演示的产品完成度。

本轮采用“关键路径优化”，而不是全产品重构。优化顺序为登录、首页、首次游戏引导、答题反馈、结算证明；任何不能直接提高上述首次体验的改动均不进入范围。

## 2. 已选方案与替代方案

### 选定：关键路径优化

保留现有 UI Toolkit、C# 应用结构、后端契约和 Sprout Lands 素材，只重排信息层级、补足首次引导、强化学习证据，并修复盲审路径中发现的稳定性或可读性问题。

优点是风险最低、可用现有测试体系回归、成果与真实产品一致。缺点是不会统一重做所有次级页面。

### 未选：全界面视觉重构

可以统一全部页面的视觉语言，但范围会扩展到十余个功能页面，回归面过大，不适合以盲审稳定性为第一目标的本轮工作。

### 未选：专用脚本化演示模式

可以缩短演示时间，但会弱化真实产品可信度，且容易让评委认为数据和流程只是演示脚本。

## 4. 产品设计

### 4.1 登录：让评委快速进入真实体验

- 登录和注册改为明确的两种状态。默认仅显示用户名、密码和登录按钮；切换到注册后才显示昵称字段。
- 保留现有森林、羊皮纸和金色设计语言，使用仓库中已有 Sprout Lands 角色、植物或 UI 素材增强品牌识别度，不生成或绘制替代素材。
- 标题下用一句话说明产品价值：通过探索、答题和间隔复习掌握英语词汇。
- 当 API 地址明确为本机回环地址时，显示“填入本地体验账号”次级操作，只填入已有测试账号，不自动提交；非本地地址不显示该操作。
- 错误反馈紧邻表单，保留用户输入，并提供可恢复的下一步，不用模糊的失败提示。

### 4.2 首页：一个主任务，三类证明

- 首屏主卡只保留一个主操作“开始今日冒险”，同时展示推荐关卡、预计词数和推荐原因。
- 今日目标与连续学习作为同一张进度摘要，不与主按钮竞争。
- 次级能力按“巩固学习”“查看成长”“更多功能”分组；默认首屏只展示复习、学习报告和 AI 学习导师三个最能证明学习闭环的入口。
- 其他能力继续可达，不删除既有功能；在大屏使用清晰网格，在较小窗口允许纵向滚动。
- 不把 CET 词书宣传为已验证的 K12 课程内容，继续沿用现有“拓展内容”和学段适配披露规则。

### 4.3 首次游戏：30 秒内明白怎么玩

- 用户首次进入游戏时显示三步轻量引导：移动角色、接近怪物、答题完成关卡。
- 引导可跳过；完成或跳过后写入本地偏好，后续进入不重复阻挡。暂停菜单提供“重新查看操作说明”。
- HUD 分为生命与得分、当前任务进度、辅助操作三组。关卡目标始终以“已完成 / 总数”可见。
- 使用已有场景素材提高装饰密度和地表层次，但装饰不改变碰撞、怪物数量、答题触发范围和关卡规则。
- 角色、怪物和可交互目标必须在森林背景上保持足够轮廓差异；不依赖颜色作为唯一识别方式。

### 4.4 答题与反馈：让学习价值可见

- 单词、题型和剩余时间形成固定头部层级；倒计时同时显示数字和颜色/长度变化，最后 10 秒进入警示状态。
- 四个答案增加 `1–4` 键盘编号，并保留鼠标选择。悬停、键盘聚焦、选中、正确和错误状态必须可区分。
- 提交后先冻结重复输入，再显示答案反馈，避免多次提交。
- 正确反馈显示词性、释义、英文例句、中文翻译，以及简短的掌握度变化说明。
- 错误反馈明确展示用户选择、正确答案和“将加入重点复习”等真实系统后果；不能在后端未确认时编造已保存状态。
- “继续冒险”保持唯一主操作，反馈内容在 1280×720 下无需滚动即可读完。

### 4.5 结算：证明学习闭环

- 首屏展示关卡结果、正确率、掌握度变化、薄弱词数量和获得奖励。
- 清楚区分游戏分数与学习指标，避免把高分直接等同于真实掌握。
- 下一步由真实结算状态决定：进入下一关、重试或回到关卡地图；最终关不显示不存在的下一关。
- 提供“复习本关薄弱词”入口；若本关没有薄弱词，则隐藏该入口并说明本关表现稳定。
- 结算保存失败时保留本地结果和重试入口，不把未同步结果显示为已上传。

### 4.6 窗口与响应式规则

- 全新本地配置首次启动以 1280×720 为目标窗口。
- 当窗口小于 960×540 时，应用尝试恢复到可读尺寸；若系统限制无法调整，则登录和首页必须可滚动，主操作不得被裁切。
- 1280×720 是盲审主验收尺寸；1440×900 用于检查留白与密度；960×540 用于检查最小可读布局。
- 不强制全屏，不覆盖用户在正常尺寸下的窗口偏好。

## 5. 技术方案

### 5.1 模块边界

- `Resources/UI/Screens/*.uxml`：调整登录、首页、引导、答题、反馈、暂停和结算结构。
- `Resources/UI/Styles/*.uss`：复用现有颜色变量与组件样式，补充响应式类、交互状态和真实素材背景。
- `Runtime/Presentation/Screens/*`：处理登录/注册状态、本地体验账号、键盘答题、反馈内容和结算展示。
- `Runtime/Gameplay/*`：仅处理首次引导触发、场景装饰密度和可视性；不改变计分与碰撞规则。
- `Runtime/Infrastructure/Storage/*`：保存“首次游戏引导已完成”偏好；保持旧数据兼容。
- `Editor/BuildCommand.cs` 与项目设置：确保新构建的默认窗口尺寸和现有双平台构建流程一致。

### 5.2 数据流

1. 登录成功后继续使用现有会话和 API 客户端。
2. 首页读取现有进度、词书和推荐结果，只改变展示优先级，不增加后端字段。
3. 游戏引导状态保存在本地；清除本地数据后可重新触发。
4. 答题仍通过现有题目、评分和结算控制器；UI 只显示已经存在或由本地确定性逻辑计算的状态。
5. 结算同步失败继续进入现有待同步队列，不丢失本地结果。

### 5.3 错误与边界

- 网络不可用：登录页给出明确离线提示；已登录且有本地内容时允许进入可用的本地路径。
- 推荐数据不完整：首页回退到关卡地图，不显示不可启动的主任务。
- 重复点击或键盘输入：答题提交期间禁用输入。
- 分辨率过小：优先恢复窗口尺寸；同时保证滚动与主按钮可达。
- 本地体验账号：只在回环 API 地址下出现，不在远程或生产 API 下暴露。
- 引导偏好损坏：按“未看过引导”处理，不阻塞游戏。

## 6. 可访问性要求

- 正文在 1280×720 下使用不低于现有 16px 等效字号，关键任务和题目明显更大。
- 所有核心操作均可通过键盘完成，并有可见焦点状态。
- 正确、错误、警告不能只依赖颜色，必须同时使用文字或图形状态。
- 对低对比度灰色按钮、计时条和辅助文字进行对比度复核。
- Unity UI Toolkit 的自动化与 macOS 辅助功能暴露能力有限；本轮验收只报告实际完成的键盘和视觉检查，不宣称完整 WCAG 合规。

## 7. 测试策略

实施遵循测试先行，每个行为变化先补失败测试，再做最小实现。

- EditMode：登录/注册状态、本地体验账号显示条件、首页信息优先级、引导偏好、键盘答案映射、重复提交守卫、结算下一步和同步失败状态。
- PlayMode：960×540、1280×720、1440×900 三种尺寸下的关键控件可见性；登录到首页；首页启动推荐关卡；首次引导；答题与反馈；暂停后恢复；结算主操作。
- 静态验证：`bash unity-client/Tools/validate-project.sh`。
- Unity 测试：`bash unity-client/Tools/run-unity-tests.sh all`。
- 双平台构建：`bash unity-client/Tools/build-players.sh`。
- 构建产物检查：`bash unity-client/Tools/validate-build-artifacts.sh`。
- 人工盲审冒烟：使用本地测试账号，在 1280×720 完成登录、首页、推荐任务、一次正确与一次错误反馈、暂停恢复和结算，并保存本轮前后对比截图。

## 8. 验收标准

1. 评委首次启动后，无需阅读外部文档即可找到登录入口和本地体验路径。
2. 登录后 10 秒内能识别唯一主任务，并能直接启动推荐关卡。
3. 首次游戏 30 秒内能理解移动、遭遇和答题目标。
4. 答题状态、倒计时、正确/错误反馈和学习后果清晰可见。
5. 结算页能证明游戏表现、学习质量和下一步之间的关系。
6. 960×540 不裁切主操作，1280×720 为完整盲审体验，1440×900 无异常留白或拉伸。
7. 现有登录、导航、关卡、答题、结算、复习和同步契约不回归。
8. 静态验证、EditMode、PlayMode、macOS/Windows 构建和产物验证全部通过。
9. 当前运行截图与优化后同尺寸截图形成可核对的前后证据。
10. 变更仅位于 `codex/unity-blind-review-optimization`，推送后不自动合并 `main`。

## 9. 非目标

- 不重写后端、数据库或 API 契约。
- 不新增真实 K12 词书、课程标准映射、教师端或家长端。
- 不重做所有次级功能页面。
- 不引入付费素材、付费生成或新的外部服务。
- 不调整计分公式、关卡数量、怪物数量或学习算法。
- 不在本轮合并、发布安装包或部署线上环境。

## 10. 迁移、回滚与停止点

本轮没有数据库迁移。新增的本地引导偏好使用独立键名，旧版本忽略该键，新版本遇到缺失或非法值时使用安全默认值。

回滚方式是继续使用原 `feat/unity-client-migration@74d7dac` 或回退新分支中的独立提交；后端和已有用户数据不受影响。推送新分支后停止，不自动创建 PR、不合并主分支、不发布构建产物。
