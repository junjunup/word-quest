# PPT 修改建议

**基于演讲稿优化版的配套调整，确保PPT和演讲稿对齐**

---

## 一、必须修改的问题

### 1. P5 技术架构页缺失关键内容
**问题：** PPT中P5只有文字描述，没有架构图截图或示意图。而演讲稿中你要"指着架构图从上到下讲"。
**建议：**
- 补充一张**系统架构图**（可以用drawio画），展示四层结构：前端(Vue+Phaser) → 后端(Express) → 数据(MongoDB) + AI服务(FastAPI→百度文心)
- 用箭头标注数据流向，特别是QuizRecord→自适应难度这条数据链路

### 2. P8-P11 算法页缺少数据流向的可视化
**问题：** 四层AI闭环在P11只用了文字描述，缺少图示。老师看PPT时一眼看不到"四个算法之间的关系"。
**建议：**
- 在P11增加一张**四层闭环流程图**：语义干扰项生成 → 编辑距离评分 → 能力值自适应 → LLM辅导，用箭头形成闭环
- 在闭环图上标注数据流：QuizRecord(answerQuality) → 自适应引擎 → 题型调整

### 3. P14 功能展示建议改为实际演示
**问题：** 纯截图没有说服力，老师更想看实际运行效果。
**建议：**
- 提前打开localhost:3000并登录test/123456
- P14时直接切换到浏览器演示，依次展示：游戏世界→答题→AI学伴对话（展示流式输出）→学习报告

## 二、建议优化的问题

### 4. P3 背景页过于拥挤
**问题：** 三列痛点+三列解决方案，信息密度太大，老师容易看花。
**建议：**
- 痛点部分保留，但将下方"本项目解决方案"改为**图标+一句话**的精简版
- 把详细方案留到后面各章节展开

### 5. P8 语义干扰项页需要对比图
**问题：** 只有文字描述"优化前vs优化后"，缺少直观对比。
**建议：**
- 增加**对比示例**：
  - 优化前：正确答案affect，干扰项apple/banana/cat → 学生排除法蒙对
  - 优化后：正确答案affect，干扰项effect/infect/afford → 学生必须理解词义
- 视觉上用两个选择题截图并排展示

### 6. P9 模糊评分页增加实际案例
**问题：** 只有一个environment的例子，不够丰富。
**建议：**
- 增加第二组案例：short词"cat"→"cut"判定为wrong（短词保护）
- 用颜色区分三档：绿色exact、黄色near、红色wrong

### 7. P10-P11 自适应难度可以合并为一页
**问题：** 分两页讲同一个算法，翻页打断思路。
**建议：**
- 合并为一页，左侧放公式+映射表，右侧放三个保护机制+四层闭环
- 省出来的时间可以多讲30秒算法细节

## 三、锦上添花

### 8. P17 核心指标页增加"工作量"数据
**问题：** 现有数据只展示功能规模，没有体现个人工作量。
**建议增加：**
- 代码量：约XX行（前端+后端+AI服务）
- 文件数：约4774个文件（含node_modules等，可以只算自己写的）
- API接口数：约50个RESTful端点
- 游戏资产：X个Phaser场景、X个Vue组件

### 9. 增加一页"AI技术应用总览"
**问题：** 老师可能想快速了解"这个项目的AI到底做了什么"。
**建议：** 在P2目录后、P3背景前，或P7 AI学伴后增加一页，用一张图展示：
```
AI技术应用矩阵：
├─ 出题层：语义干扰项生成（6维特征融合）
├─ 评价层：编辑距离模糊评分（3档判定）
├─ 路径层：能力值自适应难度（4维特征+5级映射）
└─ 辅导层：LLM上下文增强Prompt（8维注入）
```
这样可以一句话回答"你的AI做了什么"。

### 10. P19 技术栈清单可以删除或精简
**问题：** 附录页19页，实际答辩中几乎不会翻到。
**建议：**
- 直接删除，如果老师问技术栈口头回答即可
- 或者精简为一张表格，删除所有描述文字
